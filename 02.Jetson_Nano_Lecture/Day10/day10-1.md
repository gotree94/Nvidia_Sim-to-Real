## 1. 개요

### 1.1 What Is Sim-to-Real?

Sim-to-Real이란 **시뮬레이션 환경 내에서 policy를 학습**하여 실제 하드웨어에 배포하는 것.

> 최종 목표: 시뮬레이션에서 학습했지만, **실제에서도 잘 동작**하는 policy를 만드는 것

### 1.2 Sim-to-Real Gap (Reality Gap)

시뮬레이션과 현실 사이의 차이로, 극복해야 할 주요 격차:

| Gap 유형 | 설명 |
|---|---|
| **Sensing Gap** | 시뮬레이터의 센서와 실제 센서 간 차이 (노이즈, 조명, 해상도) |
| **Actuation Gap** | 시뮬레이션 모터와 실제 모터 응답 특성 차이 |
| **Physics Gap** | 마찰, 질량, 유체 등 물리 엔진의 한계 |
| **Modeling Gap** | 로봇/환경 모델링 자체의 부정확성 |

### 1.3 Why Simulation Matters

| 항목 | 설명 |
|---|---|
| **Time** | 시간적 이점 확보 (병렬 시뮬레이션, 가속 시간) |
| **Cost** | 실제 로봇 테스트보다 우수한 비용 효율성 |
| **Safety** | 실제 로봇 작업이 위험할 수 있는 시나리오 안전하게 테스트 |
| **Diversity** | 다양한 Domain Randomization(DR)을 자유롭게 수행 가능 |

### 1.4 How It Works (이번 Hands-on)

**Isaac GR00T-N1.6 VLA (Vision-Language-Action) 모델** 사용:

```
자연어 입력: "Pick up the vial and place it on the rack"
         ↓
Joint feedback + Camera observation → Policy 입력
         ↓
Motor position → 로봇 동작 수행 (시뮬레이션)
```

## 2. 사전 준비 (Windows + WSL2)

> 이 워크숍은 **클라우드 GPU 인스턴스(RTX Pro 6000)** 를 사용합니다.
> Windows 사용자는 WSL2 환경에서 Brev CLI로 접속합니다.

### 2.1 WSL2 설치

**PowerShell(관리자 권한)** 실행:

```powershell
wsl --install
```

재부팅 후 Ubuntu 실행 → 사용자 이름/비밀번호 생성.

WSL2 버전 확인:

```powershell
wsl -l -v
```

출력:
```
  NAME            STATE           VERSION
* Ubuntu-22.04    Running         2
```

### 2.2 Ubuntu 업데이트

```bash
sudo apt update && sudo apt upgrade -y
```

### 2.3 Brev CLI 설치

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/brevdev/brev-cli/main/bin/install-latest.sh)"
```

PATH 등록:

```bash
echo 'export PATH="${HOME}/.local/bin:${PATH}"' >> ~/.bashrc
source ~/.bashrc
```

설치 확인:

```bash
brev --version
```

> ⚠️ `Command not found` 시:
> ```bash
> sudo cp /root/.local/bin/brev /usr/local/bin/brev
> ```

## 3. Brev CLI로 클라우드 GPU 인스턴스 실행

### 3.1 Brev 로그인


```bash
brev ls
```

```bash
brev open <instance-name>
```

> 💡 **tmux 사용 팁:** SSH 하나로 여러 가상 터미널을 사용하려면:
> ```bash
> tmux new -s workshop       # 세션 생성
> Ctrl+B, c                  # 새 창
> Ctrl+B, n / Ctrl+B, p      # 창 전환
> Ctrl+B, d                  # 세션에서 분리 (detach)
> tmux attach -t workshop    # 다시 접속
> ```

### 7.5 Terminal 3 — Rerun Viewer (서버, 클라우드 인스턴스)

> **새 SSH 터미널** 또는 **tmux 새 창**에서 실행.

### 7.6 Terminal 4 — Rerun Viewer (클라이언트, 로컬 WSL)

> **로컬 Windows WSL 터미널**에서 실행.
> 클라우드 인스턴스의 Rerun Web Viewer를 로컬 브라우저로 포워딩.

#### 7.6.1 Brev 포트 포워딩

```bash
# WSL Ubuntu에서
brev login

# 인스턴스 목록 확인
brev ls

# 포트 포워딩 (클라우드:9876 → 로컬:9876)
brev port-forward <instance-name> 9876 9876
```

> 또는 Brev가 자동으로 포워딩을 지원하는 경우 (버전에 따라 다름):
> ```bash
> brev open <instance-name> --port 9876
> ```

#### 7.6.2 Rerun 클라이언트 연결

> **또 다른 WSL 터미널**에서:

```bash
pip install rerun-sdk

rerun --connect rerun+http://127.0.0.1:9876/proxy
```

> 정상 연결 시 `Connected to rerun server at 127.0.0.1:9876` 로그 출력.
> 이후 브라우저에서 `http://localhost:9876` 접속하여 시각화 확인 가능.

## 8. 전체 실행 순서 요약

### 8.1 진행 순서 (타이밍이 중요)

```
Step 0: 사전 준비 (최초 1회)
  ├── WSL2 + Brev CLI 설치 (로컬)
  ├── 인스턴스 생성 (brev create)
  ├── Git LFS, 저장소 클론
  ├── Docker 이미지 빌드 (teleop-docker + real-robot)
  ├── Hugging Face 로그인
  └── 모델 4개 다운로드

Step 1: Terminal 3 실행 (Rerun 서버)
  └── rerun --web-viewer --port 9876
  └── (다음 단계 진행 전에 이게 먼저 떠있어야 함)

Step 2: Terminal 4 실행 (포트포워딩 + Rerun 클라이언트)
  ├── brev port-forward ...
  └── rerun --connect rerun+http://127.0.0.1:9876/proxy

Step 3: Terminal 1 실행 (Inference Server)
  ├── docker run real-robot ...
  └── python run_gr00t_server.py ...

Step 4: Terminal 2 실행 (Simulation + Eval)
  ├── docker run teleop-docker ...
  └── lerobot_eval ... --rerun

Step 5: 브라우저로 시각화 확인
  └── http://localhost:9876
```

### 8.2 컨테이너 간 통신 구조

```
Terminal 4 (로컬 WSL)              Terminal 3 (클라우드)
┌─────────────────────┐            ┌──────────────────────┐
│ rerun 클라이언트     │◄──proxy──►│ rerun --web-viewer   │
│ port-forward:9876   │            │ port 9876            │
└─────────────────────┘            └──────────┬───────────┘
                                              │
                      ┌───────────────────────┤
                      │                       │
                      ▼                       ▼
          Terminal 1 (클라우드)      Terminal 2 (클라우드)
          ┌──────────────────┐      ┌──────────────────┐
          │ real-robot       │      │ teleop-docker    │
          │ GR00T Inference  │◄────►│ Isaac Sim + Eval │
          │ port: gRPC       │gRPC  │ --rerun 전송     │
          └──────────────────┘      └──────────────────┘
```

## 9. Sim-to-Real 개념 정리

### 9.1 Domain Randomization (DR)

시뮬레이션 환경의 다양한 요소(조명, 질감, 색상, 물리 파라미터 등)를 **무작위화**하여 현실과의 격차를 줄이는 기법.

### 9.2 GR00T N1.6 VLA Model

- **Vision-Language-Action** 모델
- 자연어 명령 → 로봇 행동으로 직접 매핑
- 1.6B / 3B 파라미터 모델 제공
- 사전 학습된 Foundation Model을 특정 태스크에 **post-training**(미세 조정)

### 9.3 이번 과정의 4가지 Sim-to-Real 전략

| 전략 | 설명 | 비고 |
|---|---|---|
| **Strategy 1:** Domain Randomization | DR 적용 + Teleop 데이터 수집 → GR00T fine-tuning | 시뮬레이션 데이터만 학습 |
| **Strategy 2:** Co-Training | 시뮬레이션 + 실제 데이터 함께 학습 | 데이터 다양성 확보 |
| **Strategy 3:** Cosmos Augment | Cosmos World Model로 데이터 증강 | 가상 데이터 생성 |
| **Strategy 4:** SAGE + GapONet | Actuation Gap 측정 및 보정 | 현실-시뮬레이션 차이 보정 |

## 10. 자주 발생하는 문제와 해결

### 10.1 Docker 명령어 관련

#### 문제 1: `docker: Error response from daemon: conflict: container name already exists`

이전 실행에서 컨테이너가 정리되지 않고 남아있을 때 발생.

```bash
# 강제 제거
docker rm -f real-robot
docker rm -f teleop

# 또는 사용하지 않는 모든 컨테이너 정리
docker container prune -f
```

#### 문제 2: `docker: permission denied`

Docker 소켓 권한이 없을 때.

```bash
sudo chmod 666 /var/run/docker.sock
```

#### 문제 3: `docker: error during connect: ... nvidia-container-runtime`

NVIDIA Container Toolkit이 설치되지 않았거나, `--device nvidia.com/gpu=all`을 지원하지 않는 경우.

```bash
# 설치 확인
nvidia-ctk --version

# 미설치 시
sudo apt install -y nvidia-container-toolkit
sudo systemctl restart docker
```

#### 문제 4: volume mount 경로가 `$PWD`로 되어 있어서 에러

Selkies 환경에서 `$PWD`가 예상과 다른 디렉토리일 때.

```bash
# 현재 위치 확인
pwd

# 반드시 workshop root여야 함
cd ~/sim2real/Sim-to-Real-SO-101-Workshop
pwd   # /home/shadeform/sim2real/Sim-to-Real-SO-101-Workshop
```

또는 아예 절대경로 `/home/shadeform/Sim-to-Real-SO-101-Workshop`로 통일.

### 10.2 Rerun 관련

#### 문제 5: `rerun: command not found`

```bash
pip install rerun-sdk
```

#### 문제 6: Rerun Viewer에 아무것도 안 보임

- Terminal 3 (rerun 서버)가 **Terminal 2보다 먼저** 실행 중이어야 함
- Terminal 2의 `lerobot_eval` 명령어에 **`--rerun`** 플래그가 있어야 함
- 방화벽/포트 막힘 확인

### 10.3 GR00T Inference 관련

#### 문제 7: `CUDA out of memory`

```bash
# 불필요한 GPU 프로세스 확인
nvidia-smi

# 필요 없는 프로세스 종료
sudo fuser -v /dev/nvidia*
```

#### 문제 8: 모델 경로 에러

```bash
# 모델 파일이 실제로 있는지 확인
ls -la /workspace/models/aravindhs-NV/grootn16-finetune_sreetz-so101_teleop_vials_rack_left/checkpoint-10000/

# 없으면 호스트에서 경로 확인 후 재다운로드
ls -la ~/sim2real/Sim-to-Real-SO-101-Workshop/models/aravindhs-NV/
```

### 10.4 네트워크 관련

#### 문제 9: Rerun 서버에 연결 안 됨

```bash
# Terminal 3에서 서버 listening 확인
# 출력 예: Serving web-viewer at http://0.0.0.0:9876

# Terminal 4에서 포트 포워딩 확인
brev port-forward <instance-name> 9876 9876
```

## 11. 문제 해결 (Troubleshooting)

> ⚠️ **docker run이 안 될 때 확인할 체크리스트 (순서대로)**

```
[ ] docker 이미지가 빌드되었는가?
     → docker images | grep teleop-docker
     → docker images | grep real-robot

[ ] 이전 컨테이너가 남아있지 않은가?
     → docker ps -a | grep teleop
     → docker ps -a | grep real-robot
     → 남아있으면: docker rm -f <name>

[ ] NVIDIA Container Toolkit이 설치되었는가?
     → nvidia-ctk --version

[ ] Docker 소켓 권한이 열려있는가?
     → ls -la /var/run/docker.sock

[ ] 현재 디렉토리가 올바른가? (volume mount)
     → pwd  (workshop root인지 확인)

[ ] 모델 파일이 모두 다운로드 되었는가?
     → ls ~/sim2real/Sim-to-Real-SO-101-Workshop/models/aravindhs-NV/

[ ] GPU 메모리가 충분한가?
     → nvidia-smi (VRAM 사용량 확인)
```

| 증상 | 해결 방법 |
|---|---|
| `nvidia-ctk: command not found` | `sudo apt install -y nvidia-container-toolkit` |
| `docker: permission denied` | `sudo chmod 666 /var/run/docker.sock` |
| `Permission denied: /home/shadeform` | `sudo chmod -R 777 /home/shadeform` |
| `CUDA out of memory` | 불필요 GPU 프로세스 종료 (`nvidia-smi` 확인) |
| `git-lfs: command not found` | `sudo apt install -y git-lfs` |
| Docker build 실패 | `docker system prune -a` 로 캐시 정리 후 재시도 |
| Container name already exists | `docker rm -f real-robot teleop` |
| Hugging Face 인증 실패 | `huggingface-cli logout && huggingface-cli login` |
| Inference server 연결 안 됨 | Terminal 1 서버 실행 확인, `--network host` 확인 |
| X11 display 오류 (일반 환경) | `xhost +` 실행, `DISPLAY` 환경변수 확인 |
| X11 display 오류 (Selkies) | `xvfb-run` 사용 또는 DISPLAY 설정 무시 |
| `lerobot_eval: command not found` | teleop-docker 이미지가 정상 빌드되었는지 확인 |
| `rerun: command not found` | `pip install rerun-sdk` |
| Rerun web-viewer 안 뜸 | `rerun --web-viewer --port 9876` 에 `--web-viewer` 필수 |
